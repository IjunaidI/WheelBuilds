# WB-086 · Retire the legacy /categories + /collections listings — design

> G11 Wave 4 (final). Finding **D1** ([audit §D](../../future/plans/2026-07-13-ux-completeness-audit.md)).
> Re-verified against current `main` (`d92089e`) 2026-07-15 — evidence inline. Storefront only.
> **Lands FIRST in the wave**: WB-095 must not re-fix titles/canonicals on pages this deletes.

## Problem
`/categories/[...category]` and `/collections/[handle]` are pre-Discovery boilerplate that lie to the shopper. `getProductsListWithSort` ([lib/data/products.ts:136](../../../storefront/src/lib/data/products.ts#L136)) hard-codes `limit: 100` regardless of the requested page, sorts only those 100, slices in memory — but returns the **real** unfiltered `count`. `modules/store/templates/paginated-products.tsx:71` (deleted by this work) computes `totalPages` from that real count, so `/categories/wheels` advertises ~144 pages: page 9 renders a truncated 4-item grid and page 10+ renders nothing at all. WB-084's `hasImage` gate runs *after* pagination (line 69) so pages silently shrink below 12 without adjusting the count. Every card then re-fetches its own product (`modules/products/components/product-preview/index.tsx:19-22` (deleted by this work)) though the list query already returned prices — an N+1 per page. Titles are still `"… | Medusa Store"` ([categories page:60](../../../storefront/src/app/[countryCode]/(main)/categories/[...category]/page.tsx#L60), [collections page:62](../../../storefront/src/app/[countryCode]/(main)/collections/[handle]/page.tsx#L62)); `params`/`searchParams` are still Next-14 sync; and the one `alternates.canonical` in the app (categories page:62-64) is a bare relative `"wheels"` which resolves against `metadataBase`'s **origin root** → `https://host/wheels`, a URL that has never existed. G10-cleanup (`60997d6`) then added all of it to [sitemap.ts:66-94](../../../storefront/src/app/sitemap.ts#L66-L94), so we are actively advertising the broken surface to Google.

## Decisions (defaults)
- **Redirect, don't rebuild.** `/store` and `/tires` already do this job with real facets, real pagination, real counts. Rebuilding a second listing stack to the same standard buys nothing and doubles the maintenance surface. Legacy URLs 301 into Discovery.
- **Delete, don't quarantine.** The re-verification killed the retention rationale: [storefront/CLAUDE.md:249](../../../storefront/CLAUDE.md) justifies keeping `modules/store/` because `SortOptions`/`RefinementList`/`PaginatedProducts` are "still imported by the categories page, collections page, `modules/categories/templates`, `modules/collections/templates`" — i.e. **only by the family this spec deletes**. The reasoning is circular and expires here. Repo-wide grep found **zero** consumers of `PaginatedProducts`/`RefinementList`/`SortOptions`/`Pagination`/`sortProducts`/`ProductPreview`/`getProductsListWithSort` outside the legacy family. Only `Thumbnail` is genuinely cross-cutting (5 live surfaces) and stays.
- **`/collections/[handle]` stays a route, not a config rule** — the brand name needs a backend lookup to build `?brands=`. `/categories/*` needs no route file at all; a `next.config.js` rule covers it.
- **Catch-all, not a wheels/tires allowlist.** `seed.ts:427-450` seeds unrelated demo categories (Shirts/Sweatshirts/Pants/Merch) that can exist in a dev DB; a generic `/:cc/categories/:rest*` → `/store` is the honest floor.

## Design (storefront only)
1. **Redirects (D1).** Append to the **existing** `redirects()` block ([next.config.js:52-60](../../../storefront/next.config.js#L52-L60), added by WB-085 — do not open a second one): `/:cc/categories/wheels` → `/:cc/store`; `/:cc/categories/tires` → `/:cc/tires`; `/:cc/categories/:rest*` → `/:cc/store`. All `permanent: true`. Order matters — the specific rules precede the catch-all. Verified the slugs are real: `ensureProductCategories` ([backend bootstrap.ts:76-119](../../../backend/src/modules/vendor-sync/pipeline/bootstrap.ts#L76-L119)) creates `name: "Wheels"`/`"Tires"` with no explicit handle, and Medusa's `ProductModuleService` derives `handle ??= kebabCase(name)` → `wheels`/`tires`.
2. **`/collections/[handle]` → a thin server redirect.** Replace the page body with: `getCollectionByHandle(handle)` → `redirect(`/${countryCode}/store?brands=${encodeURIComponent(collection.title)}`)`; unknown handle → `redirect(`/${countryCode}/store`)`. Delete `generateStaticParams`/`generateMetadata`. **The `?brands=` join is exact by provenance, not by luck**: `ensureBrandCollection` sets `title: brand` verbatim ([bootstrap.ts:126-147](../../../backend/src/modules/vendor-sync/pipeline/bootstrap.ts#L126-L147)) from the same `rep` object that feeds `buildProductMetadata`'s `brand` ([build-metadata.ts:17-21](../../../backend/src/modules/vendor-sync/pipeline/build-metadata.ts#L17-L21)) → the Meili `brand` facet ([build-search-document.ts:113](../../../backend/src/modules/vendor-sync/search/build-search-document.ts#L113)). Same untransformed string, three places. `?brands=` is also established prior art (PDP breadcrumbs, footer brand links, home shop-by-brand).
3. **Sitemap (D1).** Delete the taxonomy block ([sitemap.ts:66-94](../../../storefront/src/app/sitemap.ts#L66-L94)) — the URLs G10-cleanup added two sessions ago. Statics + Meili product URLs remain.
4. **Delete the dead family.** `app/.../categories/` (whole route), `modules/categories/`, `modules/collections/`, `modules/store/` (all of it — `templates/index.tsx`'s `StoreTemplate` is *already* orphaned since the Discovery migration; `/store/page.tsx` renders `DiscoveryTemplate`), `modules/products/components/product-preview/`, `lib/util/sort-products.ts`, `lib/data/categories.ts` (all three exports die once the page + sitemap block are gone). From `lib/data/products.ts` remove **only** `getProductsListWithSort` — `getProductsList`/`getProductsById`/`getProductByHandle` are live (cart/order enrichment, PDP). From `lib/data/collections.ts` keep **only** `getCollectionByHandle` (the new redirect calls it); `getCollectionsList` dies with the sitemap block, and `retrieveCollection`/`getCollectionsWithProducts` are pre-existing zero-importer orphans swept in the same pass. **Keep `Thumbnail`** (`modules/products/components/thumbnail/`) — 5 live importers. Also sweep `modules/products/templates/` (the legacy full PDP, zero importers — the live PDP is `modules/product-detail/`); its `product-info` carries the only remaining internal `/collections/[handle]` link, and it's inside dead code.
5. **Docs.** `storefront/CLAUDE.md` §Layout + §Discovery + §PDP: drop the now-false `modules/store/` and `modules/products/` retention notes; the `modules/products/` note narrows to "`Thumbnail` only".

## Verify
`npx next build` (the real gate — it fails on a deleted-but-imported module, and on any `"use server"` violation vitest/tsc are blind to). `npx tsc --noEmit` must stay at or below the 5-error baseline — note `lib/data/collections.ts` owns 1 of those 5, so the baseline may *drop*; record the new number in CLAUDE.md if so. Vitest: `/collections/<handle>` → `?brands=` builds the expected URL (incl. a brand with a space, e.g. `BLACKLINE FORGED`) and unknown handle → `/store`. Smoke: `/us/categories/wheels` → 301 → `/us/store`; `/us/categories/tires` → 301 → `/us/tires`; `/us/categories/anything-else` → 301 → `/us/store`; `/us/collections/fuel` → 301 → `/us/store?brands=Fuel` with real results. Grep: no importer of any deleted symbol; no `/categories` or `/collections` in `sitemap.ts`.

## Deploy
Storefront rebuild. No migration, no backend change.

## Out of scope
Rebuilding a taxonomy browse surface (Discovery **is** it). Vendor-data hygiene on the `Brand` column — the raw CSV value is never trimmed/cased, so `"FUEL"` vs `"Fuel "` could fragment one human brand across two collections; that's a vendor-sync concern, not a redirect bug. Bare country-code-less legacy URLs (`/categories/wheels`) take two hops (middleware 307 → `/us/categories/wheels`, then the 301) — identical to WB-085's shipped `/results`/`/search` behavior, accepted.
