## Problem
The flagship flows can't be driven by a keyboard or a screen reader. `Field` gained an `htmlFor` prop — and it is passed at **zero call sites in the app**: all four YMM selects ([ymm-pane.tsx:295-385](../../../storefront/src/modules/search/components/search-drawer/find-by-vehicle/ymm-pane.tsx#L295-L385)) and the Discovery price Min/Max inputs ([filter-sections.tsx:326-347](../../../storefront/src/modules/discovery/components/filter-rail/filter-sections.tsx#L326-L347)) render an unassociated `<span>` label. (WB-088's id fix covered facet *checkboxes* only — it never touched `Field`, so this half of X4 is fully open.) The cart's delete button is icon-only with no accessible name at [cart/components/item/index.tsx:126](../../../storefront/src/modules/cart/components/item/index.tsx#L126); the search input is placeholder-only.

Keyboard focus is invisible: [`wheel-builds.css`](../../../storefront/src/styles/wheel-builds.css) contains **zero** `:focus` rules file-wide. Two corrections to the audit's model: (a) `.field` (css:310-330) is **dead CSS** — no JSX consumes it, so fixing it there fixes nothing; the live controls are the `Select`/`TextInput` React components, which strip focus explicitly (`focus:outline-none focus:ring-0`) and lean on a 1px border-color shift as their only cue. (b) `.vehicle-tile` (css:358-382) *is* live and genuinely has no focus indicator at all. The wheel PDP's size/bolt cells convey selection by color only ([variant-picker.tsx:94-127,156-169](../../../storefront/src/modules/product-detail/components/hero/variant-picker.tsx#L94-L127)) — and it's now the **only** PDP surface missing `aria-pressed`, since the tire size-picker already has it.

Small orange and gray text fails WCAG AA site-wide (`#FF6A00` at 11px ≈ 2.9:1; `--ink-soft` `#8A8A8E` ≈ 3.5:1 against a 4.5:1 requirement). `middleware.ts` carries three real edge bugs. The `(checkout)` group and home have no `loading.tsx`. Analytics is pageviews only — `grep "plausible("` returns zero hits, so there is no add-to-cart/checkout/purchase signal at all. And the Algolia-era orphans are still shipping.

## Decisions (defaults)
- **X6: add a token, don't mutate `--orange`.** `--orange` has 83 `.tsx` + 11 CSS usages and only ~27 are small text — the rest are backgrounds/borders/glows (`btn-primary`, `tag-new`, `fits-chip`, `wheel-glow`, `brand-mark .dot`) carrying **white-on-orange**, a different pair that is currently fine and would silently degrade if the value moved. DESIGN.md's "surgical orange … used like a highlighter" framing says the bright value is intentional. So: **new `--orange-deep` (≈`#D14A00`, 4.6:1 on white) for sub-18px text only; `--orange` unchanged.**
- **X6: `--ink-soft` darkens in place** (`#8A8A8E` → `#6E6E73`) — DESIGN.md §2 scopes it to tertiary text / mono labels / disabled, all text roles. **The implementer greps all 77 usages first**; any border/background usage found stays on the old value explicitly rather than riding the token.
- **DESIGN.md owns the contract.** §2's token table gains `--orange-deep`, the new `--ink-soft` value, and a contrast rule (§2 has *no* mention of contrast/AA today). Token + docs + call sites change together.
- **X7 stays note-only** — but since `middleware.ts`'s matcher is already being edited, add `_next/image` to the exclusion now with a comment. It's one line, it's latent-only while `images.unoptimized: true` holds, and it removes the trap for whoever flips the optimizer.
- **X11 needs no config.** `Analytics` is already env-gated on `NEXT_PUBLIC_ANALYTICS_DOMAIN` (renders nothing when unset), and Plausible exposes `window.plausible` once loaded — so `window.plausible?.(...)` **is** the no-op-when-off behavior. One shared helper, not a guard duplicated at three call sites.

## Design (storefront only)
1. **Accessible names (X4).** Pass `htmlFor` + a matching `id` at the four YMM `<Field><Select>` pairs and the two Discovery price `<Field><TextInput>` pairs — both components already `forwardRef` and spread `...props`, so `id` flows through with **zero component changes**. `aria-label="Remove item"` on `DeleteButton` (keep the mini-cart's visible `"Remove"` children — that call site already has a name; the full cart table is the broken one). Label the search-drawer input ([header.tsx:97-115](../../../storefront/src/modules/search/components/search-drawer/header.tsx#L97-L115)).
2. **Focus visibility (X5).** `focus-visible:` rules — 2px `--orange` outline with offset — on the live surfaces: the `Select`/`TextInput` components (replacing their `focus:outline-none focus:ring-0`), and in `wheel-builds.css` for `.vehicle-tile`, `.nav-link`, `.product-card`, `.style-tile`, `.brand-chip`. **Do not add rules for `.field`** — it is dead CSS; delete it instead. shadcn's `<Button>` already has a correct `focus-visible:ring-2` — match its shape, don't re-solve it.
3. **`aria-pressed` (X5).** On the wheel PDP's size + bolt-pattern cells. Copy the two shipped references: [`hero/gallery.tsx:54-60`](../../../storefront/src/modules/product-detail/components/hero/gallery.tsx#L54-L60) (finish buttons) and [`tire/hero/size-picker.tsx:69,125`](../../../storefront/src/modules/product-detail/components/tire/hero/size-picker.tsx#L69).
4. **Contrast (X6).** Add `--orange-deep` to `.frame` in `wheel-builds.css`; darken `--ink-soft`; repoint the sub-18px accent text call sites ([label](../../../storefront/src/modules/common/components/label/index.tsx), [micro-link](../../../storefront/src/modules/common/components/micro-link/index.tsx), and the ~27 grepped `text-[var(--orange)]` usages that are small text) to `--orange-deep`. Update DESIGN.md §2.
5. **Middleware edges (X8).** All three, root-caused: **(a)** the same-URL 307 loop — a `?cart_id=X&step=…` link with no `_medusa_cart_id` cookie skips the early `next()` (line 160's third gate is false), sets `redirectUrl` to the *current* href (line 170), and never reaches the only cookie-setting branch (176-185, gated on `cartId && !checkoutStep`) → 307s to itself forever; fix by setting the cookie regardless of `checkoutStep`, and never redirecting when the target equals the current URL. **(b)** `/US/store` → `/us/US/store` → 404 — line 94 lowercases the segment but line 154 compares the **raw** segment against it, so a valid uppercase prefix reads as code-less; compare lowercased. **(c)** replace the `notFound()` at line 67 (unsupported in Edge Middleware — no boundary to catch it) with a logged passthrough.
6. **Matcher (X7 note).** Add `_next/image` to the exclusion list with a comment tying it to `images.unoptimized`.
7. **Loading coverage (X9-residual).** `loading.tsx` for home and for the `(checkout)` group (zero today). Categories/collections need none — WB-086 deleted them.
8. **Funnel events (X11).** `lib/analytics/track.ts` exporting a guarded `track(event, props?)`; call it for `add_to_cart` (PDP purchase panel), `begin_checkout`, `purchase` (order-confirmed).
9. **Cleanup.** Delete `lib/search-client.ts` (zero importers), `modules/layout/components/side-menu/` (zero importers), and `modules/layout/components/country-select/` (its only consumer was side-menu). **Keep `modules/checkout/components/country-select/`** — it is live in billing-address, shipping-address, and both account address cards; the audit's "delete country-select" must not touch it. Drop `@meilisearch/instant-meilisearch`, `algoliasearch`, `react-instantsearch-hooks-web`, `@types/react-instantsearch-dom` (all four are consumed only by the deleted `search-client.ts`). **Keep `meilisearch@0.51.0`** — that's the live Discovery client. Update `storefront/CLAUDE.md` (§Layout's `search-client.ts` + side-menu lines, the SideMenu gotcha).

## Verify
`npx next build` + `npx tsc --noEmit` at/below baseline + `npx next lint`. Vitest: the middleware trio (a cookieless `?cart_id&step` request sets the cookie and does **not** redirect to itself; `/US/store` → `/us/store` not `/us/US/store`; zero regions → passthrough + log, no throw); `track()` no-ops when `window.plausible` is undefined. Smoke (keyboard only): Tab through the YMM pane, the price inputs, and the PDP pickers — every stop has a visible outline; a screen reader announces each YMM select's label and the cart's "Remove item"; the PDP size cells report pressed state. Contrast: sample the darkened `--ink-soft` and `--orange-deep` against `#FAFAF8` for ≥4.5:1, and confirm `btn-primary`/`tag-new`/`fits-chip` still render the original `--orange`. Grep: zero importers of every deleted symbol; no `focus:outline-none` left without a `focus-visible:` companion.
